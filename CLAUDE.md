# Repository guide

A Kubernetes operator for Paperless-NGX. Go, controller-runtime, Helm.

## Commands

Never call `go test`, `helm lint` or `golangci-lint` directly — use the justfile, which is what
CI runs:

- `just check` — format, vet, lint, unit tests. Run after every change.
- `just test` — envtest. Run before every commit.
- `just e2e` — k3d, chart install, assertions. Run before opening a PR.
- `just verify` — regenerate CRDs and fail if the result is uncommitted, or if
  `Chart.yaml`'s `version` and `appVersion` diverge (release automation rewrites both).
- `just --list` — everything else.

## Layout

- `cmd/main.go` — process entry point; wires flags into `manager.Config` and starts the
  controller-runtime manager.
- `api/v1alpha1/` — custom resource types (`PaperlessInstance`) and their generated
  deepcopy code.
- `internal/controller/` — reconcilers, one per kind.
- `internal/resources/` — builders for the Kubernetes objects a reconciler applies
  (Deployments, Services, PVCs, Secrets, the CloudNativePG Cluster).
- `internal/manager/` — manager assembly (`Config`, `ControllerOptions`) and the
  leader-election ID.
- `internal/version/` — build metadata (`version.String()`), stamped in by `-ldflags` at
  build time.
- `charts/paperless-ngx-operator/` — the chart users install. Generated CRDs land in
  `templates/crds/` via `just generate`.
- `examples/` — sample custom resources referenced from the README.
- `test/envtest/`, `test/e2e/` — the medium and full verification tiers.
- `test/envtestenv/` — the importable envtest harness (`Start`). Controller tests live
  beside their controller under `internal/controller/` and run in the medium tier
  (`just test`), calling this package rather than duplicating it.

## Conventions

- English everywhere: code, comments, docs, commits, issues.
- Comments describe code, never project state or history. Three lines maximum, and only where
  the reason is not obvious from the code.
- `// SPDX-License-Identifier: AGPL-3.0-only` heads every Go file.
- Conventional Commits, enforced by a hook and by CI. Commits are GPG-signed (`git commit -S`).
- The type drives releases. `feat` and `feature` bump the minor; `fix`, `perf` and `revert`
  bump the patch; `docs`, `style`, `chore`, `refactor`, `test`, `build` and `ci` bump nothing.
  A `!` or `BREAKING CHANGE:` footer bumps the major.
- So a change to workflows, the justfile or tooling is `ci`, `build` or `chore` — never `fix`,
  even when it repairs something, or release-please cuts a release containing no change to the
  operator. This applies to a pull request title too: it becomes the commit message on merge.
- The chart must never contain `lookup`, `randAlphaNum`, Helm hooks, or annotations specific to
  one GitOps tool. Values that must be stable across renders are generated by the operator.
- The operator assumes nothing about its environment: no storage class, no ingress controller,
  no time zone. `storageClassName` is an optional pointer so that unset and empty stay distinct.
- Anything the operator generates must be overridable by a user-supplied secret reference.

## Custom resources

Group `paperless.p3l1.de`, version `v1alpha1`. Kinds keep the `Paperless` prefix. Every kind
reports `status.conditions` with a `Ready` summary condition and `observedGeneration`.
